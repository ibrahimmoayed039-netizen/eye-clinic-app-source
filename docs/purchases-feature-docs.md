# ميزة المشتريات من الموردين — دليل الإضافة

توثيق شامل لميزة **"🛒 المشتريات"** المضافة حديثًا لبرنامج إدارة عيادة النظر.

---

## 1. نظرة عامة

تمت إضافة تبويب جديد باسم **المشتريات** يتيح تسجيل فواتير الشراء من الموردين بشكل كامل، بحيث:

- يزيد **المخزون تلقائيًا** بالكميات المُشتراة.
- يُحدَّث **سعر التكلفة** لكل منتج حسب آخر عملية شراء.
- تُسجَّل **حركة الدين** على المورد تلقائيًا في كشف حسابه (بدون الحاجة لإدخالها يدويًا كما كان سابقًا).
- يمكن **تسديد دفعات جزئية** لاحقًا على أي فاتورة شراء غير مسددة.
- يمكن **طباعة** فاتورة الشراء ومعاينتها.
- عند **حذف** فاتورة شراء، يتم عكس الكمية من المخزون وحذف حركة الدين المرتبطة بها تلقائيًا، بحيث تبقى الأرقام متطابقة دائمًا.

## 3. قاعدة البيانات

### جدول `purchases` (فواتير الشراء)

| العمود | الوصف |
|---|---|
| `id` | المعرّف |
| `purchase_number` | رقم الفاتورة، بصيغة `PUR-<timestamp>` |
| `supplier_id` | المورد المرتبط بالفاتورة |
| `employee_id` | الموظف الذي سجّل الفاتورة |
| `purchase_date` | تاريخ الفاتورة |
| `subtotal` | الإجمالي الفرعي قبل الخصم |
| `discount` | مبلغ الخصم |
| `total` | الإجمالي النهائي بعد الخصم |
| `paid_amount` | المبلغ المدفوع من إجمالي الفاتورة |
| `status` | `مدفوعة` / `مدفوعة جزئياً` / `غير مدفوعة` |
| `notes` | ملاحظات حرة (مثل رقم فاتورة المورد الأصلية) |

### جدول `purchase_items` (أصناف كل فاتورة)

| العمود | الوصف |
|---|---|
| `purchase_id` | الفاتورة المرتبطة |
| `product_id` | المنتج (اختياري — يمكن أن يكون صنفًا مخصصًا بدون ربط بمنتج) |
| `description` | اسم الصنف |
| `qty` | الكمية |
| `unit_cost` | سعر تكلفة الوحدة |
| `total` | إجمالي السطر (qty × unit_cost) |

### تعديل جدول `supplier_transactions`

أُضيف عمود جديد **`purchase_id`** (اختياري، NULL للحركات اليدوية القديمة). هذا العمود يربط حركة الدين/الدفع تلقائيًا بفاتورة الشراء التي أنشأتها، مما يسمح بحذف الحركة تلقائيًا عند حذف الفاتورة، دون التأثير على الحركات اليدوية التي يُضيفها المستخدم من تبويب الموردين مباشرة.

> **ترحيل تلقائي:** عند تشغيل البرنامج بعد التحديث، يتم فحص قاعدة البيانات القديمة وإضافة العمود الجديد تلقائيًا إن لم يكن موجودًا — لا حاجة لأي إجراء يدوي، ولن تفقد أي بيانات سابقة.

## 4. نقاط الـ API الجديدة

| Method | المسار | الوصف |
|---|---|---|
| `GET` | `/api/purchases` | جلب كل فواتير الشراء (فلترة اختيارية بـ `supplier_id`, `from`, `to`) |
| `GET` | `/api/purchases/:id` | جلب فاتورة شراء واحدة مع أصنافها |
| `POST` | `/api/purchases` | إنشاء فاتورة شراء جديدة — يحدّث المخزون والتكلفة وكشف حساب المورد تلقائيًا |
| `POST` | `/api/purchases/:id/pay` | تسجيل دفعة جديدة على فاتورة شراء غير مسددة بالكامل |
| `DELETE` | `/api/purchases/:id` | حذف فاتورة شراء — يعكس الكمية من المخزون ويحذف حركة الدين المرتبطة |

### مثال جسم الطلب عند إنشاء فاتورة (`POST /api/purchases`)

```json
{
  "supplier_id": 3,
  "employee_id": 1,
  "items": [
    { "product_id": 12, "description": "إطار كلاسيك أسود", "qty": 10, "unit_cost": 15000 },
    { "product_id": null, "description": "شحن ونقل", "qty": 1, "unit_cost": 5000 }
  ],
  "discount": 0,
  "paid_amount": 50000,
  "notes": "فاتورة المورد رقم 2245"
}
```

## 5. طريقة الاستخدام من الواجهة

1. من القائمة الرئيسية، افتح تبويب **🛒 المشتريات**.
2. اضغط **"+ فاتورة شراء جديدة"**.
3. اختر **المورد** من القائمة المنسدلة.
4. أضف الأصناف بإحدى الطرق التالية:
   - النقر على بطاقة المنتج من الشبكة.
   - البحث بالاسم أو التصفية حسب الفئة.
   - مسح الباركود مباشرة (حقل مخصص لذلك).
   - إضافة **صنف مخصص** (مثل مصاريف شحن) غير مرتبط بمنتج في المخزون.
5. عدّل الكمية وسعر التكلفة لكل صنف مباشرة من الجدول عند الحاجة.
6. أدخل الخصم إن وجد، والمبلغ المدفوع فورًا (اتركه صفرًا إذا كانت الفاتورة آجلة بالكامل).
7. اضغط **"✅ حفظ فاتورة الشراء"** — سيتم:
   - تحديث كمية وتكلفة كل منتج في المخزون.
   - تسجيل الدين على المورد (والدفعة إن وُجدت) في كشف حسابه تلقائيًا.
   - فتح معاينة طباعة لفاتورة الشراء.

### من سجل المشتريات يمكنك أيضًا:
- **عرض** تفاصيل أي فاتورة سابقة.
- **طباعة** الفاتورة مرة أخرى.
- **تسديد** دفعة إضافية على فاتورة غير مسددة بالكامل.
- **حذف** فاتورة (مع تأكيد، لأن الحذف يعكس الكمية من المخزون ويحذف حركة الدين المرتبطة).

---

## 6. ملاحظات مهمة

- الأصناف "المخصصة" (بدون ربط بمنتج) لا تؤثر على المخزون، وتُستخدم لتسجيل بنود مثل الشحن أو رسوم إضافية ضمن نفس فاتورة الشراء.
- سعر تكلفة المنتج في شاشة "المنتجات" يتحدّث تلقائيًا إلى آخر سعر شراء تم إدخاله لهذا المنتج.
- كشف حساب المورد (من تبويب الموردين) سيعرض الآن حركات الشراء المُنشأة تلقائيًا من هذا التبويب، إلى جانب أي حركات يدوية تُضاف من هناك مباشرة — كلاهما يُحتسب معًا في الرصيد.

## 7. ميزة الطلبات الخاصة (📋 الطلبات الخاصة)

ميزة لتسجيل ومتابعة طلبات الزبائن لقطع مميزة غير متوفرة حاليًا بالمخزون (موديل إطار معين، عدسة نادرة...) إلى حين وصولها وتسليمها.

### الملفات المضافة
| الملف | الوصف |
|---|---|
| `src/renderer/js/tabs/special-orders.js` | واجهة تبويب الطلبات الخاصة بالكامل |
| جدول `special_orders` في `src/db/database.js` | تخزين بيانات كل طلب خاص |
| نقاط API في `src/main/server.js` تحت `/api/special-orders` | إدارة دورة حياة الطلب بالكامل |
| `buildSpecialOrderReceiptHtml` في `print-templates.js` | طباعة إيصال مرجعي للزبون عند تسجيل الطلب |

### دورة حياة الطلب (الحالات)
1. **قيد الانتظار** — تم تسجيل الطلب، لم يُطلب من المورد بعد.
2. **تم الطلب من المورد**
3. **وصلت - جاهزة للاستلام** — يظهر تنبيه بعدد الطلبات الجاهزة أعلى صفحة التبويب.
4. **تم التسليم** — نهائية، تتحول تلقائيًا لفاتورة بيع (انظر أدناه).
5. **ملغاة**

### التسليم = تحويل تلقائي لفاتورة بيع
عند الضغط على "🏁 تسليم للزبون" وإدخال السعر النهائي والكمية (مع إمكانية ربطها بمنتج موجود بالمخزون لخصم الكمية تلقائيًا)، يقوم النظام بـ:
- إنشاء **فاتورة بيع عادية** جديدة بنفس آلية تبويب المبيعات تمامًا (تظهر في سجل الفواتير والتقارير كأي فاتورة أخرى).
- احتساب **العربون المدفوع مسبقًا** تلقائيًا كجزء من المبلغ المدفوع في الفاتورة، بالإضافة لأي مبلغ إضافي يُدفع عند التسليم.
- ربط الطلب الخاص بالفاتورة الناتجة (`invoice_id`) لتتبّع لاحق.
- فتح نافذة اختيار طريقة الطباعة (عادية / حرارية) لطباعة الفاتورة فورًا، بنفس تجربة تبويب المبيعات.

> **ملاحظة:** العربون المُستلَم عند تسجيل الطلب (قبل التسليم) **لا** يظهر في إحصائيات الصندوق/الكاش إلا بعد التسليم الفعلي وتحويله لفاتورة، لأن الصندوق يعتمد على الفواتير المُصدرة فقط. إذا احتجت تتبّع العربون كإيداع نقدي فوري، يمكن تسجيله يدويًا أيضًا كـ"إيداع" من تبويب الصندوق عند استلامه.

### نقاط API
| Method | المسار | الوصف |
|---|---|---|
| `GET` | `/api/special-orders` | جلب كل الطلبات (فلترة بـ `status`, `from`, `to`) |
| `GET` | `/api/special-orders/:id` | جلب طلب واحد |
| `POST` | `/api/special-orders` | تسجيل طلب جديد |
| `POST` | `/api/special-orders/:id/status` | تحديث الحالة (تقدّم في المراحل أو إلغاء) |
| `POST` | `/api/special-orders/:id/deliver` | التسليم النهائي — ينشئ فاتورة بيع تلقائيًا |
| `DELETE` | `/api/special-orders/:id` | حذف طلب (غير مسموح إن كان "تم التسليم") |
